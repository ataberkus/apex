# Phase 2 design

APEX_BUILD.md §4 is the binding specification. The requested outcome is the complete local success-rate harness, with evidence rather than an invented benchmark win. The existing free-only instruction remains binding: no inference, credential/account/provider requests, paid/container/cloud resources or Pi core changes. MAIN and FAST remain `openrouter/meta/muse-spark-1.3-contributor`; thinking remains `xhigh`.

## Selected architecture

Extend the existing Pi package with `extensions/apex-core/index.mjs`. Fourteen independent flags (`snapshot,entrypoints,headless,contract,todo,verify,loops,bg,time,correct,diagnostics,subagents,max,recovery`) default off. The launcher accepts an Apex prefix `--apex-core FLAGS`, `--time-budget SECONDS` and `--apex-attempts N`; the latter two require their respective feature. Existing stock invocations stay unchanged. No factory starts processes, watches, sockets or timers. Per-session state initializes from the active branch and is cleared idempotently on shutdown; volatile observations are custom messages, never system-prefix timestamps. Static headless/interactive guidance uses named prompt sections, retaining Pi context-file and tool guidance.

Alternatives considered: one monolithic extension makes parallel tools, state restoration and cancellation hard to review; core patches add upstream maintenance without a missing extension seam. Bounded modules behind Pi's existing hooks are selected. Model-backed work is implemented behind an explicit policy gate, with injected deterministic completions in tests. Returning plausible fake model results in the product is rejected.

## Modules and interfaces

1. `environment.mjs`: bounded gitignore-aware depth-two snapshot and deterministic task-entry ranking. At most 2,400 UTF-8 bytes of model-visible snapshot including the top ten entry points (approximately 600 tokens, not a tokenizer guarantee). Read project manifests, never verifier/task datasets. Ignore dependency/cache/output trees; do not execute project scripts. Command probes have short timeouts and small output caps. Free-only snapshot explicitly reports the two-second external reachability probe as skipped. Tool availability, runtimes, resources, git and local service observations are best-effort and labeled if unavailable.
2. `state.mjs`: validated contract and todo state, real mutation/verification ledger, bounded enforcement and artifact checks. `apex-contract` and `apex-todo` custom entries remain compatible with Phase 1 compaction. A todo tool returns deltas, requires reasons for drops, and serializes updates. A contract tool permits explicit manual criteria when automatic extraction is blocked. Contract extraction is one guarded native FAST completion with §6.7 and usage included. Artifact checks use explicit confined paths/formats; check strings are never executed as commands. A gate needs every todo resolved, a successful verification action after the last mutation, and valid explicit artifacts. Gate continuation maximum two per user run; missing-todo steering maximum one after two turns. Aborted/error/pending boundaries never force requests. A finished-assistant preview can initially have canContinue=false: a bounded gate appends its own nonempty message, and native Pi revalidates the resulting context before continuing. No semantic-compliance claim from file existence alone.
3. `process.mjs`: `bg` start/poll/tail/kill with detached processes, redirected restrictive logs in `.apex/bg/`, opaque IDs, ownership validation and bounded output. Required services survive extension/agent exit; shutdown does not kill them. Only explicit kill removes a process owned by this manager. Bash timeout defaults are applied through mutable tool-call input, including nested calls. Native Windows background management fails clearly rather than pretending Unix detach semantics. Tests clean only their own fixtures/services.
4. `control.mjs`: near-miss argument normalization and path/precondition validation; bounded loop detection, elapsed-time threshold messages, and opt-in diagnostics. Normalize only unambiguous alias pairs; conflicts block. Preserve edit-family compatibility and validate again because Pi does not revalidate hook mutations. Interactive catastrophic-command confirmation requires real TUI UI; headless eval receives no confirmation flow. Loop notes are bounded; Muse remains xhigh. Time messages at 50/75/90 percent are appended at tool/turn boundaries, with a monotonic clock and no background timer. Persisted elapsed time and thresholds survive reload/compaction; only a new user run resets them. Diagnostics choose installed fast checkers, capture a pre-edit baseline, and emit only newly introduced errors, with bounded time/output. They never install packages or execute arbitrary extracted checks. Installed repository checkers can execute project code (including Cargo build scripts); they are explicit opt-in diagnostics, credential-stripped and bounded, not an OS sandbox.
5. `models.mjs`: depth-one fresh-context read-only `explore` and `verify`, separate max-attempt orchestration, and native retry policy configuration. Offline policy is checked before catalog/auth/SDK/fs allocation. Authorized future subagents use the exact physical Muse/xhigh, no project/session history or inherited assumptions, restricted tools and usage records. Max attempts use isolated repository copies/worktrees via an injected isolation boundary, verify each, and use a guarded judge for ties; always a distinct configuration. Current `--profile max` fails before starting Pi/inference. Retry settings are bounded; the same-model router's failed path remains sticky, with no unauthorized failover provider. Recovery cannot bypass free-only authorization.
6. `index.mjs`: one coordinator composes Pi boundary drafts with other extensions, persists bounded per-run control state, registers tools only for selected features, and injects the initial snapshot/contract once per run. Native micro-evals exercise real Pi registration, hooks, session projection and tools without making provider requests.

## Verification and evidence

Each module gets test-first tests on real temporary files and failure paths. Native gates must prove todo/gate caps, verify-after-mutation ordering, branch reload, bounded loop/time behavior, nested coherent tool results, process survival, and pre-auth denials for extraction/subagents/max. Run `npm run check`, `npm test`, `npm run micro`; inspect raw outputs and obtain an independent whole-change review. Record one ablation row per flag with all model deltas null. All default features remain off. Phase 2 acceptance (same-model pass-rate improvement outside CI) stays false until actual baselines/ablations are permitted.
