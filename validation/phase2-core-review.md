## Resolved prioritized findings

1. **P1 — Quoted catastrophic operands bypass the interactive confirmation.** `extensions/apex-core/control.mjs:170-174` matches bare `/` and `$HOME`, but not their usual double-quoted shell forms. A pure `correctToolCall` reproduction using `{mode:'tui',hasUI:true}`, `headless:false`, and a confirmation callback returning false yielded: `rm -rf /` → one confirmation, blocked; `rm -rf "/"`, `rm -rf "$HOME"`, and `sudo rm -rf -- "$HOME"` → zero confirmations, unblocked. No command was executed. This violates the interactive confirmation requirement and permits an ordinary destructive command to execute without the intended prompt. **Fix:** recognize quoted root/HOME operands conservatively while preserving the no-confirmation headless/RPC rule; add focused callback-only regressions. Root routed the fix to the control owner.

2. **P2 — Concurrent explicit kills overwrite one another in the single mailbox.** `extensions/apex-core/process.mjs:298-308` atomically replaces the same `<id>.control` file for every request. The supervisor reads that one file at 100 ms intervals and remembers only its last `killNonce` (`process.mjs` worker timer). Two legitimate callers can publish SIGKILL and then SIGTERM before the next read. The stronger request disappears; a TERM-resistant foreground command survives and the SIGKILL call times out. Atomic publication protects file integrity but does not queue distinct requests. This is a source-proven interleaving; no native process experiment was run by this reviewer. **Fix:** publish bounded per-nonce request files or serialize publication plus acknowledgment across manager instances, retaining ownership/HMAC validation and the rule against signaling persisted PIDs. Add a concurrent SIGKILL/SIGTERM regression. Root routed the fix to the process owner.

3. **P2 — Concurrent first starts can read an unfinished ownership key.** `extensions/apex-core/process.mjs:64-77` publishes `.owner` with `O_EXCL` before asynchronously writing its 32 bytes. A second first-time start catches EEXIST, immediately reads the still-empty file, and rejects with `Invalid background ownership key`. No child is allocated by the losing start, but the independent-start contract fails spuriously. **Fix:** publish complete key contents atomically without replacing an already valid key, or wait for a bounded complete initialization after EEXIST; add an injected/deterministic overlap regression. Root routed this with the mailbox finding.

4. **P2 — Python accepts deadlines that its CLI serialization makes invalid in JavaScript.** `evals/core_flags.py:17-23` accepts positive finite float/string budgets, while `evals/harbor/apex.py:207` forwards `str(float)` and `extensions/apex-core/config.mjs:15-16` permits only decimal notation. An accepted `time_budget_sec=1e-6` becomes `1e-06` and fails the launcher. Pure launcher calls confirmed `0.000001` succeeds and `1e-06` fails. **Fix:** use one finite decimal serializer for Python adapter/planner output, or align both validators on a deliberately supported numeric syntax. Keep benchmark timeouts untouched. Root is implementing the decimal serializer.

5. **P2 — Incomplete helper accounting can be reported complete after the attribution edit.** The reviewed `evals/analysis/metrics.py:169-210` assigns `missing_auxiliary=True` inside `add_message()` for incomplete/missing attributed helper usage without declaring `nonlocal missing_auxiliary`. The enclosing completeness flag therefore remains unchanged, so a trace with a priced main assistant and partial helper can retain a complete total. **Fix:** declare the nonlocal flag and cover both nonzero partial usage and absent helper usage. This was reported immediately while root was editing attribution.

6. **P2 specification gap — The snapshot omits several explicitly required environment fields.** `extensions/apex-core/environment.mjs:29-33,293-323,443-464` includes platform/architecture/resources, selected runtime/CLI versions, package script names, and local git/service observations, but no distro, current shell, user, or package-manager observations. Makefile build/test targets and pyproject build/test hints are also not extracted. These are required by `APEX_BUILD.md` §4.1; unavailable fields should be labeled rather than absent. **Fix:** add compact best-effort fields and manifest-derived build/test hints within the existing 2,400-byte cap, with no script execution. Root was informed; acceptance should not describe the current snapshot as full §4.1 coverage unless this is resolved or the scope exception is recorded explicitly.

Per root's execution ruling, this remains a documented limitation, not a request to disable the authorized checker. This review ran only injected Cargo checks; real Cargo/build-script/network containment is unverified and awaits a permitted OS sandbox.

Snapshot field/path/reason rendering is best effort inside the fixed byte cap, and declarations do not prove a package manager is installed. Port observations and background supervisor heartbeats are not service-health proofs. Required service survival and process cleanup depend on root's separately run native gate; this reviewer did not reproduce those experiments. Native Windows behavior, authorized inference, same-model router retries, max container/worktree execution, and benchmark acceptance remain unmeasured.
