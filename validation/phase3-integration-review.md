# Independent Phase 3 integration review

Reviewed `extensions/apex-features/index.mjs`, feature config/lifecycle, launcher/local command parsing, `bin/apex`, Phase 2 plan/safety cooperation and Phase 1 compaction bookkeeping against `PHASE3_DESIGN.md` and APEX_BUILD.md Phase 3. Product code was read-only for this reviewer; fixes and regression tests were applied by the root coordinator while findings were delivered.

## Findings and disposition

1. **High — checkpoint IDs could collide after tree navigation. Resolved.** The original coordinator restored a numeric counter from only the active branch while the private checkpoint manager retained records for the unchanged session ID. Navigating before a completed turn made the next capture reuse its ID; the manager's existing-record path then returned the old snapshot. `index.mjs` now derives the high-water mark from all session entries and persisted checkpoint records. The isolated coordinator reproducer observed captures `['1','2']` after a rewind, with two stored records. The focused regression checks the same result.

2. **High — undo could select a checkpoint from an abandoned branch. Resolved.** The original `/undo` chose the newest finished record from the session-wide checkpoint list even if the active branch never contained that turn. The coordinator now persists `checkpointIds` in the branch state after completion and filters manager records by that list. After navigating to the root, the isolated reproducer received refusal; the focused regression additionally refuses explicit abandoned ID `1` and selects current ID `2`.

3. **Medium — extension-local flag scoping caused duplicate confirmation. Resolved.** The original core safety cooperation queried `pi.getFlag('apex-feature-flags')` from the core extension. Pinned Pi `dist/core/extensions/loader.js` scopes `getFlag` to flags registered by that extension, so this returned undefined and retained the core confirmation before the features confirmation. A scoped-flag fixture now proves one confirmation and refusal for a catastrophic shell call. The fix uses an inert lifecycle WeakMap keyed by the stable native session manager, with owner-scoped removal on reinitialization/shutdown; it also communicates explicit eval mode. The first draft keyed the mode by cwd and failed the intended eval-before-cwd trap by inspection; the final WeakMap implementation avoids that access and its regression passes.

4. **Medium — internal eval switch could consume the task. Resolved.** Pinned Pi parses unknown extension switches before learning their declared type. For feature/eval selection with the positional task preceding explicit model/thinking options, the original generated `--apex-eval task` consumed the prompt as a switch value. The launcher now emits internal `--apex-eval=true`. The pure pinned CLI parser reproducer reports `messages: ['task']` and flag value `true`; the public Apex prefix remains a boolean switch. A focused regression verifies this exact arrangement.

5. **Medium — selected skill paths failed in checkout paths containing spaces or `#`. Resolved.** The original resource discovery used `URL.pathname`, which preserves URL escapes such as `/tmp/apex%20checkout/skills/...`. Native skill discovery requires filesystem paths. The final coordinator uses `fileURLToPath`, matching the launcher. This is a source-verified portability fix; the reviewer did not install a second package or run a native loader from a spaced checkout.

6. **High — real extension-local flags let core corrections erase selected Phase 1 tool definitions. Resolved.** The same flag-scoping root cause also affected the pre-existing core initialization query for `apex-context-flags`: native core scope returns undefined even when the context extension selected edit/search features. Core correction wrappers consequently re-registered native definitions and removed the selected edit tool's conventional `old_string` schema. The root coordinator reported a test-first scoped fixture failure proving the schema was absent before the fix. The final context extension publishes its exact selected feature array in a module-local WeakMap keyed by the native session manager, and core consumes `contextFeaturesFor(ctx)` when constructing correction definitions; the old `getFlag` fallback serves fixtures or runs with no published context. Initialization replaces the published value and shutdown releases only the same value, so a stale owner cannot delete a newer registration. This reviewer read the three changed modules and independently ran only `scoped native flags preserve Phase 1 edits when core corrections are enabled`: **1 passed, 0 failed, 0 skipped**, in 2.068 seconds. Its separate extension APIs enforce native declared-flag scope and its final edit definition concretely contains `parameters.properties.edits.items.properties.old_string`. No broader checks were run for this follow-up; guarded native and global reruns remain owned by the root.

7. **Medium — future authorized plan/review templates interpreted literal dollar replacement syntax. Resolved.** JavaScript string-valued replacement expands `$&`, `$$` and related sequences, so requirements containing those literals could change when inserted into a template. The initial fix made all three plan/review task/diff replacement arguments callbacks; the final shared `fill` helper preserves the same literal-return behavior. The root's preserved `phase3-placeholder-red.log` shows the stubbed `sendUserMessage` assertion `prompted.includes(task)` failing for `Inspect literal $& and $$ replacement strings.` before the fix. `phase3-placeholder-green.log` shows the same regression passing with **31 focused integration/workflow tests passed, 0 failed, 0 skipped**. This reviewer inspected those logs and source; no additional test run was performed for this follow-up. The future-authorized path used a fixture stub, without actual SDK inference.

8. **Medium — sequential review placeholder replacement could rewrite literal task markers. Resolved.** Inspecting the callback fix revealed that inserting a task containing `{diff}` before replacing the template's diff slot still rescanned the task and replaced its literal marker, leaving the actual diff slot unresolved. The root's `phase3-template-red.log` concretely shows refusal of the exact requirement string `Keep current behavior and literal {diff}, $& and $$`. The final shared helper replaces `/\{(task|diff)\}/g` in one pass over the original template, returning dictionary values through a callback and preserving unknown markers. Both plan and review use this helper; inserted values are never rescanned. Read-only inspection confirms that the strengthened review fixture keeps the complete literal task, exactly its one `{diff}` occurrence, and the real `+current`/`-before` diff. The preserved `phase3-template-green.log` records **31 combined integration/workflow tests passed, 0 failed, 0 skipped**, in 2.395 seconds. This reviewer only read source/log evidence and did not rerun additional tests or change product code.

No unresolved high/medium integration defect was identified in the reviewed revision.
