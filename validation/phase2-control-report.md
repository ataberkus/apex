## Integration contracts

- `prepareCorrectableArguments(toolName, input)` is synchronous, returns fresh normalized arguments for known built-in tools, and throws on invalid types/conflicting aliases. Unknown custom tool input is passed through. Use it in a native tool's `prepareArguments` **before** Pi schema validation. Pinned Pi 0.99.2 prepares arguments, validates them, then runs `tool_call`; later input mutations are not revalidated.
- `correctToolCall(event, ctx, {headless=true, confirm}={})` is asynchronous. Allowed calls return `undefined` and mutate the existing `event.input` object in place. Blocked calls return `{block:true, reason:string}` with a reason bounded to 3,500 bytes and preserve the original input on validation/confirmation failure. `confirm(command,event,ctx)` must return `true` to permit a detected catastrophic command; default confirmation uses `ctx.ui.confirm`. It can prompt only when `headless===false`, `ctx.hasUI===true`, and `ctx.mode==='tui'`.
- `createLoopBreaker({maxNotes=2})` returns `observe(event)` and `reset()`. Observe native `tool_result` events, including reconstructed nested results. A note is `{kind:'failure'|'read'|'ping-pong', n:3, failure_summary:string, thinking:'xhigh'}`. The summary is at most 1,200 UTF-8 bytes. No model setting or provider is changed. At most the configured number of notes is returned until reset; history maps have at most 64 keys each.
- `createTimeTracker({seconds,now})` returns `poll()` and `reset()`. `poll()` returns an array of newly crossed thresholds: `{threshold:0.5|0.75|0.9, remaining:number, total:number, elapsed:number}`. Durations are seconds; the injected clock is milliseconds. Thresholds emit once, including catch-up after a long boundary gap. Backwards clock samples cannot increase remaining time. No timer is created.
- `createDiagnostics({cwd,runCommand})` returns asynchronous `before(event)` / `after(event)` and synchronous `reset()`. Both methods return `{status:'baseline'|'diagnostics'|'skipped',toolCallId:string,checker:string|null,errors:string[],newErrors:string[],reason?:string,truncated?:boolean}`. Root should render **only** `newErrors` from `status:'diagnostics'`. `before` emits no runtime note. Pending baseline state is keyed by the exact native tool-call id, so nested and sibling tools remain independent; at most 64 baselines are retained. Reset invalidates in-flight observations.

The diagnostics adapter contract is `runCommand(command,args,{cwd,timeoutMs,maxOutputBytes,networkAllowed:false,env}) -> {code|exitCode|status,stdout,stderr,timedOut?,truncated?}`. Real commands receive a 1,000 ms version-probe timeout, 5,000 ms checker timeout, and combined 65,536-byte output cap. Checker/error output is bounded to 40 rows and 8,000 bytes; incomplete baselines and incomplete post-edit output are skipped instead of claiming a trustworthy difference.

## Implemented behavior and limits

Near-miss aliases are narrowly selected by built-in tool: `file_path/filePath -> path`; read `start_line -> offset`, `max_lines -> limit`; write `text -> content`; edit `old_string/old_text -> oldText`, `new_string/new_text -> newText`; grep `query -> pattern`, `ignore_case -> ignoreCase`, `max_results -> limit`; find `glob -> pattern`, `max_results -> limit`; ls `max_results -> limit`; shell `cmd -> command`. Identical redundant aliases are accepted; conflicts block. Edit supports native arrays, legacy shorthand, single-object and JSON-string preparation and up to 128 replacements.

Filesystem arguments must stay within cwd lexically and after resolving existing or dangling symlink ancestors. Accepted aliases become canonical physical paths. The edit precondition opens only bounded regular text files (2 MiB) with nonblocking/no-follow flags and validates through Pi's native edit operations with captured bytes and a no-op writer. It preserves native multi-edit matching, Unicode/whitespace tolerance, BOM/CRLF handling, and ambiguity/overlap rejection. Failure candidates are approximate, bounded suggestions that never cause edits. The native edit subsequently rechecks under its own mutation queue. A hook is not an isolation boundary against an independently malicious concurrent process renaming ancestor directories after validation.

Catastrophic-command recognition is a narrow interactive guard, not a shell interpreter or exhaustive security boundary. It does not evaluate aliases, functions, command substitutions, computed paths, arbitrary execution wrappers, or all shell/PowerShell grammar. Those limits do not change the real-TUI-only confirmation requirement. Root's elapsed-time restoration and diagnostic environment whitelist were preserved during the P1 correction.

Diagnostics support `write` and `edit`; other mutation-capable shell/custom tools are skipped. New `write` targets receive an empty intrinsic baseline without creating placeholders. Existing files must be regular and at most 2 MiB. Selection uses installed executables: Node syntax checking for `.js/.mjs/.cjs`; `tsc --noEmit` for TypeScript/JSX; ruff then pyright for Python; `go vet` for Go; `cargo check --offline --locked` for a confined Rust manifest. No package-manager command, install, extracted arbitrary check, or task/verifier/dataset detection is used. Ruff ignores project configuration/cache. Cargo's build process may execute project/dependency build scripts, as permitted by the root's checker execution ruling, and writes target artifacts under `.apex/diagnostics-target`; Go/Cargo receive offline/toolchain-download-disabled environment settings. Other checker-specific project settings and imports retain their installed tool's behavior.

Error differences compare a multiset of path/code/message identities while ignoring line/column movement. This avoids calling shifted old errors new, while preserving newly added duplicates. Project-wide/checker import effects and concurrent mutations to the same file can limit attribution to one individual edit; these notes are observations, not semantic verification evidence. Timeout/output-cap enforcement terminates an owned Unix process group; native Windows child termination lacks the Unix descendant guarantee and the Unix fixture is explicitly skipped there.

All model-success, accuracy, latency, billing, and pass-rate deltas remain unmeasured. MAIN/FAST stay Muse and thinking stays `xhigh`.
