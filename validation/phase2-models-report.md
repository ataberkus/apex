## Delivered behavior

`createSubagentTools({policy,runSession?,runChecks?,loadSdk?})` returns native `explore` and `verify` definitions. Both require `{task:string}`; verify optionally accepts `{commands:string[]}` with at most four explicitly listed noninteractive test/check commands. Every offline denial occurs before reading prompt files or cwd, invoking a session/check adapter, importing the SDK, resolving auth/catalog data, or creating an isolation copy. Model and effort must remain exactly `openrouter/meta/muse-spark-1.3-contributor` and `xhigh` under an explicitly paid-enabled policy.

Each permitted run has a new empty history, exact `prompts/explore.md` or `prompts/verify.md` contents, depth one, and only the native tool names `read`, `grep`, `find`, `ls`. The future SDK path uses `SettingsManager.inMemory`, `SessionManager.inMemory`, a controlled DefaultResourceLoader with all five suppression flags, no ambient resource discovery/reload, and explicit ModelRuntime/model arguments to createAgentSession. Startup binds extensions before prompting. A guarded runtime proxy checks the current authorization, cancellation, exact physical model and xhigh neutral reasoning on every request, including lazy preparation and inner auth calls; async preparation/auth is checked again before provider dispatch. Fully stub regressions prove policy revocation after the first tool-use turn prevents a second auth/stream, and revocation during auth preparation prevents dispatch in the same turn. Cache warming, compaction and retries are disabled for these auxiliary sessions. Installed `rg` performs search; there is no dependency/tool download fallback. Tools confine real paths to the repository, bound text results and reads, and exclude image reads. A continuing tool loop aborts at eight turns; final answers on the eighth turn succeed. Nested calls cannot start another subagent.

Subagent results use coherent native text content and details with `status`, exact model/effort/depth, normalized token/cost usage, check evidence, and truncation. Model-visible final output is capped at 4096 UTF-8 bytes. Token and cost totals are reconstructed from bounded component fields, avoiding inconsistent reported totals. Partial incurred usage survives cancellation and native session failures. Actual attempted helper usage is also returned at the native top-level `usage` field so Pi tool-result hooks and saved ToolResult messages retain it. Attribution is explicit in `details.apexAux` (`version`, helper kind, physical provider/model, attempted, complete). Pre-callback denials omit top-level usage. Missing or zero attempted usage is explicitly incomplete, rather than proof of a free request. Valid optional `reasoning` and `cacheWrite1h` subsets are preserved without adding them to output/cacheWrite totals again; aggregate optional values are omitted if any accounting source lacks that subset.

Verifier commands use parsed fixed argv without a shell. Node listener/module-injection flags, shell metacharacters, installs, unrecognized command families and oversized lists are rejected before adapters. The real default local check fixture runs `node --test` in a new repository copy, captures command/exit/output/duration evidence, verifies source files are unchanged, and removes its own copy. `runMaxAttempts({policy,cwd,task,attempts=2,createIsolation?,runAttempt,verifyAttempt,judge?,signal})` is always a separate `configuration:'max'`. It requires real attempt/verification adapters, allocates distinct copies, preserves current uncommitted file content, verifies each successful attempt, ranks passing checks before score, and invokes a guarded judge only for a top passing tie. All-failed candidates retain `winner:null`. Usage includes attempts, verification and judging; serialized results, candidates and exceptions include explicit `usageComplete` booleans. Every adapter invocation is accounted, including thrown helpers without usage, so missing/zero accounting cannot become a complete zero-cost observation when private aggregation metadata is dropped by JSON serialization. Fully observed nonzero callback usage remains complete even for failed candidates or cleanup failures; aborts, malformed judge choices, reused/source paths and cleanup errors are covered. Default copies are limited to 50000 entries and 300 MiB, omit git/runtime/cache state, rewrite internal symlinks into the copy, reject external links and clean only owned directories. Returned candidates contain bounded captured text and check evidence; the orchestrator does not apply winning edits to the source repository.

Offline returns `applied:false`. Existing stock Pi retry defaults are separate from this opt-in profile. Router stickiness is preserved by the existing exact-model failed/previous path; this module adds no failover provider.

## Source audit and limits

The pinned 0.99.2 SDK sources were inspected locally: `dist/core/sdk.{js,d.ts}` (tools are names; explicit runtime/settings/session/resource seams), `resource-loader.{js,d.ts}` (default reload still performs discovery despite resource flags), `agent-session.{js,d.ts}` (bindExtensions startup, prompt options, subscriptions, abort/dispose), and `settings-manager.{js,d.ts}` (RetrySettings and cacheWarming). The request proxy relies on pinned ModelRuntime ordinary property/receiver semantics (no JavaScript private fields); re-audit this seam before upgrading Pi. No api-specific completion reasoning option is fabricated; native sessions set xhigh and the SDK uses the neutral streamSimple reasoning path.

Repository copies isolate ordinary working-directory writes and are not an operating-system security sandbox. Test code can still perform absolute-path writes or network operations if a future authorized caller executes untrusted project checks; the runner strips provider credentials and startup environment variables and sets npm offline mode, but cannot provide an OS-level network/filesystem deny boundary. Copies are bounded; very large repositories fail explicitly. Explicit local checks are executed sequentially with 30-second time limits and 4096-byte output capture. Tool searches use 10-second limits and 16384-byte output capture.

Provider billing/retry behavior, semantic exploration/verifier quality, real max attempts, judge calibration, full container isolation and benchmark pass-rate improvements remain unmeasured.
