# Phase 2 state module report

Scope: `extensions/apex-core/state.mjs` and `tests/core-state.test.mjs`. No shared integration/core files, installations, provider requests, credential reads, or network operations were performed for this module.

## Interface

`createTaskState({cwd,branch=[],persist=()=>{},policy,complete?,enforceTodo=false,enforceContract=false})` returns `begin`, `snapshot`, `extractContract`, `contractTool`, `todoTool`, `observeTool`, `onTurn`, and `beforeSettle`.

- `begin(task,{newRun=false}={})` is awaitable. The same restored task resumes by default. `newRun:true` always creates a fresh explicit identity, including for an identical prompt, and resets criteria, todo, extraction attempts, boundary counters, and verification.
- `snapshot()` returns detached JSON-compatible values: task/taskId, contract criteria/source/usage, todos/nextId, turns/lastTurn, todoSteers, gateContinuations, extraction attempted/status/reason/usage, and ledger sequence/lastMutation/verification/pending/pendingCount.
- `persist(customType,data)` supports the coordinator's native `pi.appendEntry`. State entries use `apex-contract`, `apex-todo`, and `apex-task-state`. The todo envelope also embeds the bounded control state so Phase 1 compaction, which copies only contract and todo verbatim, retains task identity and caps. Unidentified legacy state does not seed a different task.
- `extractContract(task,ctx,{signal}={})` checks the captured and live policy before registry/model/prompt/completion access. It permits at most one attempted extraction per task. The authorized future path calls native registry completion using exact physical `openrouter/meta/muse-spark-1.3-contributor`, `xhigh`, no tools, the existing §6.7 prompt, a bounded output cap, and the caller's signal. It validates usage, model identity, response structure, criteria, and active branch/task identity. Injectable deterministic completions appear only in tests; there is no runtime synthetic fallback. Valid response/error usage is captured before cancellation, policy or stale-branch handling. Returned usage and accounting retain the originating taskId even if a later task resets diagnostic state.
- Each actually invoked contract completion persists exactly one dedicated `apex-helper-usage` custom entry: `{version:1,requestId:'<origin-task-id>:contract:1',taskId,kind:'contract',provider:'openrouter',model:'meta/muse-spark-1.3-contributor',usage?,status:'complete'|'failed'|'aborted'|'stale',complete}`. Offline/pre-request denials emit no accounting entry. Missing/invalid usage is omitted and never substituted with zero. A fully reported terminal `stop` response sets `complete:true`, even when a local task/branch/policy change then prevents publishing its criteria. Partial error/aborted responses and thrown error usage are retained with `complete:false`. These dedicated records provide billable evidence; repeated contract/todo/control snapshots are diagnostic state rather than additional billed requests.
- `observeTool(event)` accepts native calls/results, with optional execution start/end deduplicated by identity. The coordinator needs only call/result hooks, including nested calls.
- Boundary methods return `{entries,continue?}` and preserve earlier extension drafts. Todo enforcement and contract enforcement are independent constructor choices; verification never invents a missing todo requirement when todo is disabled.

Native tool `contract` parameters: `{action:'set'|'list',criteria?:[{id,requirement,check,artifact?:{path,format,contains?}}]}`. Criteria keep exact JSON values. `check` is opaque descriptive text and is never executed. A set seeds todo entries; changed criteria reopen their matching resolved todo.

Native tool `todo` parameters: `{action:'list'|'add'|'update'|'done'|'drop',id?,text?,status?:'pending'|'in_progress'|'done'|'dropped',reason?}`. Add permits an explicit id; otherwise ids are T1, T2, etc. Updates are serialized and return only changed-item deltas. List returns the full list. Dropped transitions require a nonempty reason. Both tools declare structured output and sequential execution.

## Enforcement and limits

Mutating tools (`edit`, `write`, `apply_patch`, `patch`), powershell/background actions, and ambiguous/unknown bash invalidate previous verification at both start and completion, including failed attempts. Recognized successful verification must come from an actually observed checker call, an actual native result with numeric `exit_code:0`, unchanged mutation generation since that checker began, and no pending mutations. A checker that overlaps an edit cannot prove that edit, even if it completes later. Text claiming success and summary-only nested statuses cannot establish verification. A later failed/incomplete checker clears prior success.

Recognized commands are bounded syntactic families (Node test/check, npm/pnpm/yarn test/check/typecheck/lint scripts, pytest/unittest, ruff/pyright, tsc noEmit, Cargo test/check, Go test/vet, make test/check). Shell composition, redirects/substitutions, help/version and known external-helper flags are not proof. This is an observation ledger, not a claim that arbitrary custom checker code is side-effect-free or that a passing checker proves every semantic criterion.

Gate continuation is capped at two per explicit user task; missing-todo steering is capped at one after two completed turns. Multi-step detection uses explicit numbered/bullet steps or structured criteria rather than another offline model call. Abort/error, pending messages, uninitialized tasks, and malformed native contexts never force requests. Source-backed Pi ruling: an ordinary completed final-assistant preview has `canContinue:false`; a nonempty native custom-message draft makes the resulting context continuable, and Pi rechecks it after committing the draft. This case is permitted and tested, with every continuation accompanied by its own message. No unconditional continuation is returned.

Artifacts require explicit cwd-confined exact paths and formats. Traversal, incompatible suffixes, final/parent symlinks, nonregular files, and files over 1 MiB fail. Text is checked as UTF-8; JSON is parsed; CSV quoting/row widths are checked; binary formats use bounded signature/trailer/container structure checks, with office main entries required. Supported formats: text, json, csv, pdf, png, jpeg, zip, docx, xlsx, pptx. Explicit text `contains` constraints are checked literally. Binary checks are structural checks, not full application-level rendering, semantic validation, antivirus scanning, or integrity certification. An artifact path existing by itself never creates a semantic-compliance claim.

Contract criteria are capped at 64 and 32 KiB; todos at 128; text fields are bounded. Persisted pending mutation identifiers are capped at 128 entries and 256 characters each, with an exact live pending count; all live mutations still block success. Finished tool identities are pruned while pending identities remain tracked. Reload with unfinished mutations invalidates historical verification instead of assuming an interrupted edit finished cleanly.

All test fixtures are local, freshly created, and removed. Future model behavior, actual provider usage/cost, and pass-rate improvements remain unmeasured. Synthetic authorized tests do not relax the product's offline policy.
