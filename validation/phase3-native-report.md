# Phase 3 native offline contract gate

`scripts/micro-phase3.mjs` is import-inert and uses a bounded child to load the installed Pi 0.99.2 SDK. It selects `openrouter/meta/muse-spark-1.3-contributor` with `xhigh`, disables cache warming, retry and automatic compaction, and supplies only fixture context and explicitly selected project skill paths. No factory starts a process. The child has a 30 second deadline and an output cap; its newly allocated process group owns its bounded Git and CLI subprocesses. The parent removes its fixture in `finally`.

Focused verification: `node --test tests/phase3-micro.test.mjs` passed **5/5** under a whitelisted environment, `PI_OFFLINE=1`, offline npm configuration and a localhost registry. The final focused run completed in 7.20 seconds. Both owned JavaScript files passed `node --check`. The initial test-first run failed all five tests because the gate export was absent. Later runs caught missing coordinator integration and the learnings filename change before the final passing run.

## Counter mechanics and fault behavior

The SDK child replaces fetch/WebSocket, HTTP(S), socket/TLS, DNS and datagram entrypoints with counted denials. `ModelRuntime.create` receives counted credential-store denials, a null models path and disabled model network/refresh. Runtime/model auth, inference and runtime-key entrypoints are replaced with counted denials. The physical Muse model is obtained from the installed local registry; session prompt streaming is also replaced with the inference denial. The pinned registry's local refresh seam accepts only explicit `allowNetwork:false` and is isolated from auth discovery. Package resolution is replaced by an empty local result because the pin resolves packages before applying its `no*` resource flags.

Ambient AGENTS/system/settings/models/auth and `.pi`/`.agents` discovery outside the newly allocated fixture is separately counted and refused. Child environments contain only the declared public execution variables, fixture agent directory, offline switch and optional absolute public Node path. Actual CLI children also deny SDK module execution, credential-file access and network entrypoints and return their counters for aggregation.

Passing evidence has **network/auth/inference/credentials = 0/0/0/0**, ambient discovery attempts zero, provider calls zero and benchmark runs zero. Fault regressions remove the real feature tool-call guard, allow an attempted ambient discovery, or interrupt an allocated fixture. Each fails honestly, keeps provider/auth/credential/network counts zero, and removes its owned fixture. Unknown fault modes are rejected before allocation. Import tests reject SDK/extension loading and fixture allocation during module import.

## Limits

These are mechanical offline integration contracts. User/assistant records and token/cost fields are explicitly script-seeded fixtures; no response was generated, no provider spend was measured, and no benchmark or model-routing accuracy result follows from these checks. The native tool-definition harness runs the installed definition plus native before/after and execution hooks; native nested calls use the installed callable validation and tool runner. Local subprocesses are controlled fixture Git, a denied printf-only bash fault and guarded CLI inspections; JavaScript guards are not an OS network sandbox. TUI approval interaction, adversarial filesystem races, full recovery/compaction performance, in-flight durable replay and production task quality remain outside this gate. Core checkpoint/workflow/safety/reader unit suites cover their broader contracts separately.
