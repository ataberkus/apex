# Phase 3 design

Implement APEX_BUILD.md §5 daily-driver features locally on Pi 0.99.2. Preserve free-only execution, MAIN=FAST openrouter/meta/muse-spark-1.3-contributor, xhigh, no Pi core patches/installations, no credentials or provider/account calls. Public read-only documentation lookups are permitted; they are not inference. All behavioral experiments remain opt-in and empirical effects unmeasured. The user’s autonomous working agreement authorizes design, implementation, review and local delivery without generic skill handoff approvals.

## Architecture and alternatives

Add a native features extension with nine independent flags: cost,checkpoints,review,plan,remember,skills,safety,report,resume. Keep package skill/prompt resource lists empty by default. Selected skills are discovered through native resources_discover; templates are internal command prompts so a bare expansion cannot bypass plan enforcement. Options precede Pi/task args. Explicit eval mode disables all learnings load/write, not dataset identification. CLI report/resume are manual selectors and never initialize an SDK for inspection/dry-run.

Use independent modules coordinated by hooks. A monolithic extension would mix filesystem restore, untrusted session parsing and UI requests; generic middleware/core patches would add upstream maintenance. Native APIs plus bounded modules are selected. No factory starts timers/processes/sockets. Session startup/reload/tree restores active-branch state; shutdown removes only Apex statuses and restores its changed tool selection.

## Components

- Accounting: pure session/branch aggregation, native uncached/cache-read/cache-write/output/thinking usage, per-task/session totals, routed model/context %, native cost estimates labeled distinctly from invoices, helper completeness and replay dedup. Offline session report has explicit byte/4 category estimates and top consumers, never pretends to know exact input attribution. Missing data stays unknown. Footer uses setStatus, retaining native footer/other extensions.
- Checkpoints: persistent private shadow Git separate from the user’s repository/index. Capture before a mutating turn’s first tool call; concurrent siblings share the capture. Finish records changed paths/current hashes; undo checks post-checkpoint conflicts before restoring selected changes. Preserve dirty and untracked source; protect ignored dependencies, private state and external/symlink paths. Cap files/bytes and Git subprocess time. No git clean/reset/stash mutation in the user repository. Reopen uses owned records; restore transactional preparation and rollback protect failures.
- Plan/review/learnings: /plan enters read/search-only mode enforced in tool_call, including nested/deferred calls; bash/unknown tools blocked. Authorized future prompting uses pi.sendUserMessage, not nonexistent ctx.prompt. Current offline plan can save explicit user-supplied Markdown; completed native planning output is atomically saved to exact PLAN.md then prior tools restored, also restored on cancel/error/shutdown. Core todo/verification is suppressed only during this explicit plan phase. /review passes current bounded diff/requirements to the guarded independent Phase 2 verify seam, returning an honest offline refusal now. remember is deferred, serialized, confined and disabled before read/write in eval; explicit learnings append to AGENTS-style contextFiles only when selected, preserving native context.
- Safety: TUI-only confirmation from tool annotations and conservative built-in classifications; eval/headless never add dialogs. Hints are unverified, pending approval is bounded/cancelable, block if declined. Nested/deferred calls use identical hook checks. Unknown destructive/open-world tools are not assumed safe. This is approval UX, not an OS sandbox.
- Skills: ten short Pi package skills with real read-only domain probe scripts: debugging, test-writing, profiling, build systems, Python packaging/environments, numerics/fitting, HTTP/web servers, databases, git surgery and security hardening. No production/database/network/destructive actions in probes, no installs or dependency assumptions. Content/routing/assets verified, model routing accuracy unmeasured. They are project Pi assets, not ChatGPT personal skills; personal checkout/push/install instructions do not apply. Commit them in Apex Git history; no global installation or direct skill-file delivery.
- Resume: inspect exact native JSONL without mutating it; preserve header/tree/recent state, detect torn tail/pending tools and warn before replay. Native exact-session CLI routing remains guarded by free-only policy. pi-durable is absent from the installed pin; public catalog confirms a separate runtime but its README/source fetch is blocked. Do not invent a drop-in API, install it or claim in-flight side-effect replay. Native completed-turn restore is the tested fallback; optional durable integration remains an explicit limitation.

## Verification

Test-first real files, shadow Git, conflict/restore/symlink/concurrency/abort/eval denial, unknown billing, readonly nested calls, scoped UI cleanup and guarded commands. Native gate executes Pi registration/command hooks/resources/session persistence without model/auth/credential/transport calls. Final npm run check → npm test → npm run micro under a whitelisted environment and offline npm configuration. Independent whole-feature reviews, committed source, packaged CLI smoke, full-history bundle, original traces unchanged, credential scans and saved artifacts. No fixture counts justify pass-rate gains, lower dollars per solve or default promotion.

## Source rulings

Extension commands bypass input hooks; enforce modes in tool_call. ctx.getSystemPromptOptions and before_agent_start options expose skills/contextFiles; no pi.getResources API. getContextUsage can return null counts. Native footer uses all entries, branch views serve active task state. Native stash example is memory-only and cannot satisfy persistent undo. Reconstruct custom state from active branch and preserve Phase 1 compaction bookkeeping. Work remains in the already isolated managed workspace on dedicated apex-phase3 branch; no new worktree, dependency install, remote push or merge.
